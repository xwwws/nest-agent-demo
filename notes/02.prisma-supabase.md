# 目标二 · Prisma 配置（Supabase）

> 本章要做什么：掌握 Prisma 7 相对旧版的三大变化（连接串移位、client 生成器升级、强制 driver adapter），并学会如何连接 Supabase PostgreSQL、执行数据库迁移。

## 2.1 Prisma 7 新变化

| 变化点 | 旧写法（≤6） | 新写法（7） |
| --- | --- | --- |
| 连接串位置 | `schema.prisma` 的 `datasource.url` | 移到 `prisma.config.ts` 的 `datasource.url` |
| client 生成器 | `prisma-client-js` | `prisma-client`（ESM + 自定义 output） |
| 查询引擎 | 内置 Rust binary engine | 需显式用 **driver adapter**（`@prisma/adapter-pg`） |

> 一句话：**连接串挪到 config，client 生成方式升级，运行时必须配 driver adapter。**

## 2.2 配置文件要点

- **schema.prisma**：`datasource` 只留 `provider = "postgresql"`，**不再写 `url`**；`generator` 用 `prisma-client`，`output = "../generated/prisma"` 把 client 生成到项目内便于 import。
- **prisma.config.ts**（本项目命名为 `prisma7.config.ts`）：用 `defineConfig` 定义，`datasource.url` 从这里注入；Prisma 7 **不再自动加载 `.env`**，顶部需手动 `import 'dotenv/config'`。

## 2.3 Driver Adapter 集成

`PrismaService` 继承 `PrismaClient`，构造时 `new PrismaPg({ connectionString })` 生成 adapter，`super({ adapter })` 传入：

| 点 | 说明 |
| --- | --- |
| 依赖 | `@prisma/adapter-pg` + 底层 `pg` |
| `super({ adapter })` | 用 adapter 连接，替代默认引擎 |
| 生命周期 | `OnModuleInit` 里 `$connect`，`OnModuleDestroy` 里 `$disconnect` |
| `@Global()` | `PrismaModule` 标 `@Global()`，全应用无需重复 import |

## 2.4 Supabase 连接

Supabase PostgreSQL 三种连接方式：

| 连接方式 | 端口 | 特点 |
| --- | --- | --- |
| Direct（直连） | 5432 | 无连接池，适合本地/迁移 |
| Transaction pooler | **6543** | pgBouncer 事务模式，适合无状态查询，不支持部分事务/Prepare |
| Session pooler | 5432 | pgBouncer 会话模式，支持完整会话，适合迁移 |

本项目 `.env` 两个连接串：

- **`DATABASE_URL`**：应用运行时用（走 pooler，带 `?schema=public`），缓解连接数压力。
- **`DIRECT_URL`**：`prisma migrate` 专用（session mode），因 transaction 模式可能中断迁移脚本。

## 2.5 迁移（migrations）

目录：`migrations/<时间戳>_init/migration.sql` + `migration_lock.toml`（锁 provider，勿手改）。

| 命令 | 作用 |
| --- | --- |
| `pnpm --filter api exec prisma generate` | 重新生成 client 到 `generated/` |
| `pnpm --filter api exec prisma migrate dev` | 开发：生成迁移 + 应用 |
| `pnpm --filter api exec prisma migrate deploy` | 生产：只应用已有迁移 |
| `pnpm --filter api exec prisma migrate status` | 查看迁移状态 |

## 2.6 易错点

1. 改 schema 必须重新 `prisma generate`，否则 client 类型/API 是旧的。
2. Prisma 7 不自动读 `.env`，config 顶部必须 `import 'dotenv/config'`。
3. `output` 路径相对 schema 文件（`../generated/prisma` 相对 `prisma/`）。
4. ESM 下 import 生成物要带 `.js` 后缀（`client.js`）。
5. 迁移用 `DIRECT_URL`，pooler transaction 模式会中断 migrate。
6. adapter 与 client 版本需一致（本项目均 7.10.0）。
7. `.env` 含敏感信息，务必 `.gitignore`。
