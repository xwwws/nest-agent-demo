# 目标五 · 全局验证管道（ValidationPipe / CORS / 全局守卫）

> 本章要做什么：把 `main.ts` 的全局配置独立成章——落地全局 `ValidationPipe`（DTO 校验从「手动 validate」升级为「自动」）、补上 CORS 跨域、并注册全局守卫；同时讲清「手动校验」与「全局管道」的差异，以及 `useGlobalGuards` 与 `APP_GUARD` 的重复注册坑。
>
> 前置：目标四（class-validator / class-transformer）、目标八（APP_GUARD 全局守卫）。

## 5.1 全局 ValidationPipe 落地（main.ts）

本项目在 `main.ts` 注册了全局管道，DTO 校验从「手动 validate」升级为自动：

```ts
app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,              // 剔除 DTO 未声明的字段
    // forbidNonWhitelisted: true,   // 有未声明字段直接报错
    forbidNonWhitelisted: false,   // 允许前端多传入字段
    transform: true,              // 自动转 DTO 实例（触发 @Transform）
    transformOptions: { enableImplicitConversion: true },
  }),
);
```

| 配置项 | 作用 |
| --- | --- |
| `whitelist: true` | 自动剔除 DTO 里没声明的字段 |
| `forbidNonWhitelisted: false` | 允许前端多传入字段 |
| `transform: true` | 把 body 自动转成 DTO 实例（省掉手动 `plainToClass`） |
| `enableImplicitConversion` | 按 TS 类型元数据做隐式转换（如 `"1"` → `1`） |

> 落地后，目标四里 `auth.controller` 的手动 `plainToClass + validate` 写法可以简化了。

## 5.2 手动校验 vs 全局 ValidationPipe

| 对比 | 手动校验 | 全局 ValidationPipe |
| --- | --- | --- |
| 代码量 | 每接口重复写 | 零重复，装饰器声明即可 |
| 失败行为 | 手动返回（本例 200） | 自动抛 400 BadRequest |
| transform | 手动 | 自动转 DTO 实例 |

手动校验是「教学写法」，地道做法就是 `app.useGlobalPipes(new ValidationPipe(...))`，让 `@Body()` 自动校验。

## 5.3 CORS 与全局守卫（main.ts）

同时补上了跨域与全局守卫的 `main.ts` 侧注册：

```ts
app.enableCors({
  origin: 'http://localhost:3000',   // 只允许 web 前端来源
  methods: 'GET,HEAD,PUT,PATCH,POST,DELETE',
  allowedHeaders: 'Content-Type',
  credentials: true,
});
app.useGlobalGuards(app.get(JwtGuard));
```

| 配置 | 说明 |
| --- | --- |
| `origin` | 允许的跨域来源（本项目前端 `http://localhost:3000`） |
| `credentials: true` | 允许携带 Cookie 等凭证 |
| `app.useGlobalGuards(app.get(JwtGuard))` | 用容器里的实例注册全局守卫 |

## 5.4 守卫重复注册（useGlobalGuards vs APP_GUARD）

> ⚠️ **守卫重复注册**：`main.ts` 的 `useGlobalGuards` 与 `app.module.ts` 里的 `APP_GUARD + useClass: JwtGuard` **二选一即可**，同时存在会让 JwtGuard 每个请求执行两遍。

推荐保留 `APP_GUARD`（可 DI 注入 Reflector，见目标八 8.7），删掉 `useGlobalGuards` 这行。

## 5.5 易错点

1. **`enableImplicitConversion` 的副作用**：会按类型隐式转换，某些场景可能把 `"0"` 转成 `0` 导致校验误判，需留意。
2. **`forbidNonWhitelisted: true` 过严**：客户端多传一个字段就 400，团队需约定好入参；不想报错可只开 `whitelist` 静默剔除。
3. **`transform: true` 是 `@Transform` 生效的前提**：不开 transform，DTO 里的 `@Transform(({ value }) => value.trim())` 不会触发（见目标十一 11.5）。
