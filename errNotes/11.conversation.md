# 目标十一 · Conversation 模块（CRUD + 归属校验 + 软删除）

> 本章要做什么：新增 Conversation（会话）模块，掌握 Nest CLI `resource` 脚手架的结构、Prisma **一对多关系**（User 1:N Conversation）、用 `@User()` 装饰器**自动关联当前登录用户**，并实现完整的 **CRUD + 归属校验 + 软删除**。
>
> 前置：目标三（CRUD）、目标四（DTO 校验）、目标八/九（守卫）、目标十（@User 装饰器）。

## 11.1 模块结构（nest g resource 脚手架）

`nest g resource conversation` 一键生成的标准五件套，本项目实际只用其中四个，`entity` 是空壳：

| 文件 | 职责 |
| --- | --- |
| `conversation.module.ts` | 组装 controller + service |
| `conversation.controller.ts` | 路由 + 参数解析（`@Controller('conversation')`） |
| `conversation.service.ts` | 业务逻辑 + 数据库操作 |
| `dto/create-conversation.dto.ts` | 入参定义 + 校验 |
| `dto/update-conversation.dto.ts` | 更新入参（复用 create） |
| `entities/conversation.entity.ts` | 空类，未使用（见 11.8） |

controller 现已实现 5 个路由：

| 方法 | 路由 | 说明 |
| --- | --- | --- |
| `POST` | `/conversation` | 新建会话 |
| `GET` | `/conversation` | 当前用户会话列表 |
| `GET` | `/conversation/:id` | 查单条 |
| `PATCH` | `/conversation/:id` | 更新 |
| `DELETE` | `/conversation/:id` | 软删除 |

> 本项目用 Prisma 而非 TypeORM，`entities/` 里的空类没有意义，可删。

## 11.2 Prisma 一对多关系（User 1:N Conversation）

`schema.prisma` 里一个 User 对应多条 Conversation：

```prisma
model User {
  // ...其他字段
  conversations Conversation[]        // 反向关系字段（非物理列）
}

model Conversation {
  id        String   @id @default(uuid())
  title     String
  content   String
  userId    String                    // 物理外键列
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  user      User     @relation(fields: [userId], references: [id])
  isDelete  Boolean  @default(false)  // 软删除标记
}
```

| 概念 | 说明 |
| --- | --- |
| 外键字段 | `Conversation.userId`，真实存在于表里 |
| 关系字段 | `Conversation.user` + `User.conversations`，只存在于 Prisma 层面，不落库 |
| `@relation(fields, references)` | 声明外键字段 `userId` 指向 `User.id` |
| 一对多 | 「一」侧写数组 `Conversation[]`，「多」侧写单个 + 外键 |
| `isDelete` | 软删除标记位，`remove` 只把此位置 `true`，不物理删行 |

> 改 schema 后需 `prisma migrate` + `prisma generate`（本项目本次新增了 `add_conversation`、`add_conversation_content` 等迁移，并在模型上追加了 `isDelete` 字段）。

## 11.3 create：用 @User() 关联当前用户

创建会话时**不需要前端传 userId**，而是从 token 解出的当前用户身上取：

```ts
// controller
@Post()
create(@Body() dto: CreateConversationDto, @User() user: JwtPayload) {
  return this.conversationService.create(dto, user);
}

// service
async create(dto: CreateConversationDto, user: JwtPayload) {
  return await this.prisma.conversation.create({
    data: { ...dto, userId: user.id },   // 展开 DTO 再补 userId
  });
}
```

| 要点 | 说明 |
| --- | --- |
| `@User()` | 复用目标十的自定义装饰器，取 `req.user`（由 JwtGuard 注入） |
| `user.id` 来源 | 登录签发的 payload `{ id, email, name }` |
| `{ ...dto, userId }` | 把 DTO 字段展开后追加外键，`data` 必须含 `userId` |

## 11.4 查询 findAll / findOne（归属过滤）

**核心思想：查询时把 `userId` 一并塞进 `where`，天然限定「只能看自己的会话」。**

```ts
// 列表：只查当前用户
findAll(user: JwtPayload) {
  return this.prisma.conversation.findMany({
    where: { userId: user.id },
  });
}

// 单条：id + userId 双重条件，别人的 id 查不到
findOne(id: string, user: JwtPayload) {
  return this.prisma.conversation.findFirstOrThrow({
    where: { id, userId: user.id },
  });
}
```

| 要点 | 说明 |
| --- | --- |
| `where: { userId }` | `findMany` 的 where 可用任意字段，按归属过滤 |
| `where: { id, userId }` | 双条件锁定「id 对应 + 属于本人」，防越权（水平越权） |

| 方法 | `findUnique` | `findFirst` / `findFirstOrThrow` |
| --- | --- | --- |
| where 条件 | 仅唯一字段（`@id`/`@unique`） | 任意字段组合（可带 `userId` 归属过滤） |
| 找不到时 | 返回 `null` | `findFirst` 返回 `null`；`findFirstOrThrow` 抛 P2025 |
| 适用场景 | 按主键/唯一键精确定位 | 需附加过滤条件（如归属校验）时 |

> 因为 `userId` 不是唯一列，`{ id, userId }` 这种复合条件只能用 `findFirst` 系列，不能用 `findUnique`。

## 11.5 update 与 remove（软删除）

```ts
// 更新：updateMany 支持非唯一 where，返回 { count }
update(id: string, dto: UpdateConversationDto, user: JwtPayload) {
  return this.prisma.conversation.updateMany({
    where: { id, userId: user.id },
    data: dto,
  });
}

// 删除：软删除，不物理删行，只置 isDelete = true
remove(id: string, user: JwtPayload) {
  return this.prisma.conversation.updateMany({
    where: { id, userId: user.id },
    data: { isDelete: true },
  });
}
```

| 对比 | 物理删除 | 软删除（本项目） |
| --- | --- | --- |
| Prisma 方法 | `delete` | `updateMany({ data: { isDelete: true } })` |
| 数据 | 行被彻底删掉 | 行保留，仅打标记 |
| 可恢复 | 不可恢复 | 改回 `false` 即可恢复 |
| 后续查询 | 无需过滤 | 需加 `isDelete: false` 过滤（见 11.8） |

**`update` vs `updateMany`（为什么这里改用 `updateMany`）**：

| 方法 | `update` | `updateMany` |
| --- | --- | --- |
| where 条件 | 仅唯一字段（`@id`/`@unique`） | 任意字段组合（可带 `userId` 归属过滤） |
| 返回值 | 更新后的完整记录 | `{ count: number }`（受影响行数） |
| 匹配多条 | 不允许（where 必须唯一） | 可一次更新所有匹配行 |
| 适用场景 | 按主键精确更新单条 | 带归属条件 + 软删除标记（本项目） |

> 软删除的典型场景：会话/订单/消息等「用户可删但后台要留痕/可恢复」的数据。

## 11.6 UpdateConversationDto：PartialType 复用

更新接口的 DTO 不必把 `title/content` 再写一遍，用 `PartialType` 让所有字段变为可选：

```ts
import { PartialType } from '@nestjs/mapped-types';
import { CreateConversationDto } from './create-conversation.dto';

export class UpdateConversationDto extends PartialType(CreateConversationDto) {}
```

| 概念 | 说明 |
| --- | --- |
| `PartialType` | 来自 `@nestjs/mapped-types`，把 create DTO 的每个字段都变成可选（`?`） |
| 继承的校验 | 复用 create 的全部 `@IsString`/`@IsNotEmpty`/`@Transform` 规则 |
| 用途 | 更新时只需传要改的字段，未传的保持原值 |

## 11.7 @Transform 修剪输入（class-transformer）

`CreateConversationDto` 里对字符串做「去首尾空格」：

```ts
@IsNotEmpty()
@IsString()
@Transform(({ value }) => value.trim())   // 落库前去掉首尾空格
title: string;
```

| 概念 | 说明 |
| --- | --- |
| `@Transform(fn)` | `class-transformer` 装饰器，在 `plainToInstance`/ValidationPipe 转换时改写字段值 |
| `value` | 转换前的原始值 |
| `trim()` | 去首尾空格，避免 `"  hi  "` 这种脏数据入库 |

> `@Transform` 只在开启 `transform: true` 的 ValidationPipe 下才触发（见目标五 5.1）。

## 11.8 待优化点 / 易错点

1. ✅（已解决）**`findUnique`/`update` 的「唯一 where」约束**：上一版 `findUnique({ where: { id, userId } })` / `update({ where: { id, userId } })` 会编译报错（`userId` 非唯一列）。现已改用 `findFirstOrThrow` + `updateMany`，两者都接受非唯一字段的 `where`，归属校验方向不变、方法名修正（见 11.4、11.5）。
2. **软删除后查询未过滤 `isDelete`**：`findAll` / `findOne` 现在只按 `userId` 过滤，软删除的会话仍会被查出来，`isDelete` 标记失去意义。应在查询条件里补 `isDelete: false`。
3. **`findFirstOrThrow` 抛出的异常未转 404**：找不到记录时抛 `PrismaClientKnownRequestError`（P2025），NestJS 默认会返回 500。需 try/catch 转 `NotFoundException`，或配 Prisma 异常过滤器。
4. **`updateMany` 返回的 `count` 未转 404/403**：`update` / `remove` 现在返回 `{ count }`，`count === 0` 表示「不存在或非本人」，应据此抛 404/403，否则前端既拿不到明确反馈、也不知道是否真的更新成功。
5. **`entities/conversation.entity.ts` 是空壳**：Prisma 项目用不到，可删。
6. **`create` 未兜底外键冲突**：`userId` 若不存在会抛外键约束错误，生产需捕获并转 400/404。
7. **守卫重复注册**：见目标五 5.4，`useGlobalGuards` 与 `APP_GUARD` 择一。
