# 目标六 · bcrypt 存储密码

> 本章要做什么：理解为什么密码不能明文或快速哈希存储，掌握 bcrypt 的「慢 + 带盐」设计、盐与成本因子的作用、`hash`/`compare` 用法，并避开常见坑。

> 深度原理手册见 `errNotes/2.bcrypt.md`，本块是浓缩版。

## 6.1 为什么不能明文/快速哈希

| 存储方式 | 问题 |
| --- | --- |
| 明文 | 库泄露 = 密码直接暴露，且用户常复用密码 |
| MD5 / SHA-256 | 设计目标是「快」，GPU 每秒可试数十亿次，扛不住暴力/彩虹表 |

**结论**：密码要存「慢 + 带盐」的哈希，这正是 bcrypt 的设计目标。

## 6.2 三个特性

bcrypt（1999，基于 Blowfish）是专用密码哈希算法：

1. **慢**：单次约 100ms，刻意 CPU 密集，GPU 加速有限。
2. **内置盐**：自动生成随机盐并嵌入输出，同密码每次结果不同。
3. **可调成本**：硬件升级后可调大计算量。

Node 生态两包：`bcrypt`（C++ 原生，快，需编译，本项目用）、`bcryptjs`（纯 JS，免编译，慢约 30%）。

## 6.3 盐（Salt）

**盐 = 哈希前拼在密码上的随机字符串。** 同密码 + 不同盐 → 完全不同哈希。解决两个问题：**彩虹表失效**、**相同密码不可见**。

> bcrypt 的盐自动生成、自动嵌入哈希串，无需单独存列，`compare` 会自解析。

## 6.4 成本因子（salt rounds）

`bcrypt.hash(password, 10)`，计算量随轮数指数增长：

| rounds | 单次耗时 | 说明 |
| --- | --- | --- |
| 8 | ~25ms | 偏快 |
| 10 | ~100ms | 业界默认，本项目用这个 |
| 12 | ~300ms | 更安全 |
| 14 | ~1.2s | 高安全场景 |

设计意图：合法登录几乎无感，攻击者「十亿次尝试」贵到不可行。

## 6.5 哈希串结构

```
$2b$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy
 算法  成本   盐（22字符）        哈希值（31字符）
```

- `$2b` 算法版本，`$10` 成本因子（2^10 = 1024 轮）。
- 总长固定 **60 字符**，数据库列 `varchar(60)` 即可。
- 关键：盐和成本因子都自包含在哈希串里，`compare` 无需额外参数。

## 6.6 本项目用法

- 注册：`data.password = await bcrypt.hash(data.password, 10)`，落库的是 60 位哈希串。
- 登录：`const ok = await bcrypt.compare(明文, 哈希)`，从哈希串解析盐 + 轮数重算比对。

两条安全细节：

1. 用户不存在 / 密码错误返回同一句「邮箱或密码错误」，防用户枚举攻击。
2. 用异步 `compare` 而非 `compareSync`——100ms 计算不应阻塞事件循环。

## 6.7 常见坑

1. 用 `===` 比较两次哈希 → 必然失败，永远用 `compare`。
2. 密码列太短 → 哈希固定 60 字符，`varchar(60)` 起步。
3. rounds 太小/太大 → 4 形同虚设，16 登录要等十几秒。
4. 注册不兜底唯一冲突 → email `@unique` 冲突应 catch P2002 抛 409。
5. 同步 API 阻塞 → `hashSync` / `compareSync` 会卡住 Node 进程 100ms。
6. 哈希写进日志 → 可被离线爆破，日志只记 email 不记密码字段。

## 6.8 与 argon2 对比

| 维度 | bcrypt | argon2 |
| --- | --- | --- |
| 发布时间 | 1999 | 2015（密码哈希竞赛冠军） |
| 抗 GPU | 一般 | 强（吃内存） |
| 生态 | 极成熟 | 主流化中 |
| API | `hash/compare` | `hash/verify`（同形） |

**结论**：教学项目 + 生态成熟 → bcrypt 足够；新起生产项目 → 可选 argon2id（OWASP 首选）。
