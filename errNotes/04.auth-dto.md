# 目标四 · Auth 模块（DTO 验证）

> 本章要做什么：掌握用 `class-validator` + `class-transformer` 给入参做校验与转换，理解手动校验和全局 `ValidationPipe` 的差异，为 Auth 模块的注册/登录接口加上健壮的入参校验。

## 4.1 结构

认证模块负责「注册 + 登录」，三层结构与 users 一致，额外多了 `DTO/` 目录放入参定义（`auth.dto.ts`、`login.dto.ts`）。

## 4.2 DTO 定义（class-validator）

DTO 用 `class-validator` 装饰器声明校验规则：

| 装饰器 | 作用 |
| --- | --- |
| `@IsNotEmpty()` | 非空（`''`/`null`/`undefined` 都不通过） |
| `@IsString()` | 必须是字符串 |
| `@IsEmail()` | 必须是合法邮箱 |
| `@IsInt()` / `@IsNumber()` | 整数 / 数字 |
| `@Min(n)` / `@Max(n)` | 数值范围 |
| `@IsOptional()` | 字段可选（配合其他规则） |
| `@Length(min, max)` | 字符串长度范围 |

> 每个装饰器都支持 `{ message: '自定义文案' }` 覆盖默认报错。

## 4.3 class-transformer 转换

| 函数 | 作用 |
| --- | --- |
| `plainToClass(Cls, obj)` | 普通对象 → 类实例（触发装饰器） |
| `classToPlain(obj)` | 类实例 → 普通对象（序列化） |
| `validate(obj)` | 执行校验，返回错误数组 |

> 关键点：**装饰器只在「类实例」上生效**，直接校验普通对象会得到空结果，所以必须先 `plainToClass` 再 `validate`。

## 4.4 手动校验流程

当前 controller 写法：`接收 body → plainToClass 转实例 → validate 校验 → 有错返回 / 无错进 service`。

> 注意：当前失败分支返回 HTTP 200 + 错误对象，规范做法是抛 `BadRequestException`（见 4.5）。

## 4.5 全局 ValidationPipe（推荐）

手动校验是「教学写法」，地道做法是 `main.ts` 里 `app.useGlobalPipes(new ValidationPipe(...))`，让 `@Body()` 自动校验：

| 配置项 | 作用 |
| --- | --- |
| `whitelist: true` | 自动剔除 DTO 里没声明的字段 |
| `forbidNonWhitelisted: true` | 有未声明字段时直接报错 |
| `transform: true` | 自动把 body 转成 DTO 实例（省掉 plainToClass） |

| 对比 | 手动校验 | 全局 ValidationPipe |
| --- | --- | --- |
| 代码量 | 每接口重复写 | 零重复，装饰器声明即可 |
| 失败行为 | 手动返回（本例 200） | 自动抛 400 BadRequest |
| transform | 手动 | 自动转 DTO 实例 |

> 本项目 `main.ts` 已于目标五阶段注册全局 ValidationPipe，controller 里的手动校验可简化（见 `05.global-validation-pipe.md`）。

## 4.6 bcrypt 密码处理

| 概念 | 说明 |
| --- | --- |
| `bcrypt.hash(明文, rounds)` | 生成带盐哈希；rounds 是成本因子（10 约 100ms） |
| 盐（salt） | 每次随机生成并嵌入结果，同密码两次 hash 不同 |
| `bcrypt.compare(明文, 哈希)` | 从哈希串解析盐和因子，重算再比对 |
| 为什么不能直接比 hash | 盐随机，`hash(明文) === 存的值` 永远不成立 |

> **安全细节**：登录时「用户不存在」和「密码错误」返回同一句「邮箱或密码错误」，防用户枚举攻击。

## 4.7 待优化点

1. ~~改全局 ValidationPipe~~（已完成：全局 ValidationPipe 已于目标五落地，见 `05.global-validation-pipe.md`）。
2. 登录成功应签发 JWT（现在只返回 message，Phase 2 接 `@nestjs/jwt`）。
3. DTO 命名不统一：`RegisterDTO` vs `LoginDto`，建议统一驼峰。
4. `LoginDto.email` 声明可选却配 `@IsNotEmpty()`，登录邮箱应必填。
5. `RegisterDTO.name` 强制非空，但 schema 里 `name String?` 可空，需对齐。
6. 密码强度不足，可加 `@MinLength(8)`。
