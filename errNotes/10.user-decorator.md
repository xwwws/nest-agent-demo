# 目标十 · @User 参数装饰器 + req.user 注入时机

> 本章要做什么：掌握用 `createParamDecorator` 自定义 `@User()` 参数装饰器，从请求里优雅取当前用户；并彻底搞清楚 **`req.user` 到底是什么时候被放进 request 的**。

> 承接目标九：验签通过后，controller 怎么优雅拿到当前用户？本块讲 `@User()` 装饰器，以及 **`req.user` 到底何时被放进 request**。

## 10.1 为什么需要 @User

不用装饰器要写 `@Req() req: Request` 再 `req.user`，且 `req` 是 `any`。自定义 `@User()` 直接返回 `request.user`，语义清晰、类型可控：

```ts
@Get('/profile')
profile(@User() user: any) { return user; } // user 即 req.user
```

## 10.2 createParamDecorator 实现

`@User()` 用 `createParamDecorator` 定义，回调里拿 `ExecutionContext` 再取请求：

```ts
export const User = createParamDecorator((data, ctx: ExecutionContext) => {
  return ctx.switchToHttp().getRequest().user; // 从 request 取 user
});
```

| 概念 | 说明 |
| --- | --- |
| `createParamDecorator(fn)` | 自定义参数装饰器工厂（`@nestjs/common`） |
| `ExecutionContext` | 当前执行上下文，可切到 HTTP/WS/RPC |
| `ctx.switchToHttp().getRequest()` | 拿到底层 Express 的 `req` |

## 10.3 req.user 是何时被放进 request 的（重点）

结论先行：**`req.user` 不是 NestJS 自动放的，也不是 controller 赋值的，而是 Passport 在「验签成功、调用完 `validate()`」之后自动挂载的，发生在守卫阶段。**

```text
请求到达
  │
  ▼
JwtGuard.canActivate()                    ← 全局守卫最先拦截
  │
  ├─ 命中 @Public/@PublicWhiteList ──→ return true（req.user 此时为空）
  │
  └─ 未命中 → super.canActivate() → passport.authenticate('jwt')
        │
        ▼
     JwtStrategy：jwtFromRequest 提取 token + secretOrKey 验签
        │
        ▼
     验签通过 → 调用 validate(payload)
        │
        ▼
     validate 返回 payload ──→ passport 自动挂载：req.user = payload   ★ 注入点
        │
        ▼
     canActivate 返回 true → 放行
        │
        ▼
     拦截器/管道 → 控制器 → @User() / @Req() 读 req.user
```

| 阶段 | 谁在做事 | req.user 状态 |
| --- | --- | --- |
| 守卫之前 | — | 空（undefined） |
| 守卫 canActivate（公开路由） | JwtGuard 直接放行 | 仍空 |
| passport 验签 + validate | JwtStrategy | 验签通过后由 passport 赋值 |
| 控制器 | @User() / @Req() | 已就绪，可读 |

关键点：

1. **注入者是 Passport 框架**：`validate(payload)` 的返回值就是最终 `req.user`，`@nestjs/passport` 内部会把它写进 `request.user`（默认 `userProperty: 'user'`）。
2. **注入时机在「守卫执行期间」**：具体在 `super.canActivate()` → `passport.authenticate()` 验签成功的回调里完成，早于拦截器、管道、控制器。
3. **`@User()` 只是读取**：它只是从 `request.user` 取值的语法糖，本身不产生 user——没有守卫在前面注入，它读到的是 undefined。

## 10.4 易错点

1. **公开路由读 `req.user` 必为空**：放行未走 passport（见 9.6）。
2. **没挂守卫就取不到 user**：`@User()` 依赖守卫先注入，路由若无 `JwtGuard`（局部或全局），`req.user` 恒 undefined。
3. **`validate` 返回什么，`req.user` 就是什么**：当前 `return payload`，所以 `req.user = { id, email, name }`，不含密码。
4. **别在 controller 里再手动 verify**：守卫已验签并注入，重复验签纯属浪费。
